# startup.md — run this FIRST, every single time

**Paste this at the top of every Antigravity session, before the Backend, Frontend, Integration,
Dataset or Circuit prompt. It is the startup protocol. Do not skip it, including on a session
where you think you already know the project.**

You are starting work on **RackSense**, a rack capacity early-warning system (hackathon problem
statement AO-02). Before you write a single line of code, do the five steps below and show me
the output of each.

---

## STEP 0 — Read the ground truth

Read these files completely. They outrank anything you remember, infer, or prefer:

| File | What it decides |
|---|---|
| `rules.md` | How you are allowed to work. Non-negotiable. |
| `shared/api-contract.md` | Every endpoint, payload, enum and timing budget. The backend and frontend are **face-to-face** against this file. |
| `shared/architecture.md` | The four layers, the analysis methods, what we refuse to do. |
| `shared/tenant-isolation.md` | Roles, scoping, and the naming rule (**Data Center Dashboard**, never "admin"). |
| `shared/hardware-connections.md` | Pin maps and the MQTT payload the backend must parse. |

If any of these files is missing from the workspace, **stop and tell me** instead of guessing.

---

## STEP 1 — Produce the graph (`graph.md`)

Create or refresh **`graph.md`** at the repository root. This is the "graphify" output: a
visual map of what actually exists right now, generated by reading the workspace — not from
memory and not from this document.

It must contain these four Mermaid diagrams, in this order:

1. **Module graph** — every source directory and the imports between them.
2. **Data-flow graph** — sensor → MQTT topic → ingest → store → analysis → API → WebSocket →
   UI component. Follow the real code; where a link does not exist yet, draw it dashed and
   label it `PLANNED`.
3. **API surface map** — every route that exists in code, grouped by resource, each annotated
   with the roles allowed to call it. Mark any route **not** in `shared/api-contract.md` in red
   as `CONTRACT DRIFT`.
4. **Proposal state machine** — the real states implemented in code for
   `PROPOSED → DISCUSSING → APPROVED_PENDING_TAP → AUTHORIZED / REJECTED / EXPIRED`, with any
   transition that is missing marked `TODO`.

Below the diagrams add a short table: **Implemented / Partial / Not started** per subsystem
(ingest, storage, forecast, change-point, attribution, power, AI, approval, audit, frontend,
firmware).

Rules for `graph.md`:
- It is **generated from the workspace**, every run. If the code changed, the graph changes.
- It never contains aspirational boxes drawn as if they exist. Dashed + `PLANNED` only.
- Regenerate it at the **end** of the run too, so the next session starts from truth.

## STEP 2 — Produce the context file (`.agents/context.md`)

Create or refresh **`.agents/context.md`**. This is the working memory that survives between
sessions. Keep it under 400 lines; it is a briefing, not a diary.

Required sections:

```markdown
# RackSense — Context
_Last updated: <ISO timestamp> by <which prompt was run>_

## Contract
- CONTRACT_VERSION in shared/api-contract.md: <x.y.z>
- Backend implements: <x.y.z>   Frontend built against: <x.y.z>
- Drift detected: <none | list>

## Current state
<2–5 sentences. What runs end to end today. What does not.>

## Subsystem status
| Subsystem | State | Where it lives | Notes |

## Decisions made (append-only — never delete a row)
| Date | Decision | Why | Who/what prompted it |

## Open questions for the human
<Only things that genuinely block you. Never invent an answer and proceed silently.>

## Known limitations we are deliberately keeping
<e.g. power is estimated, MQ135 ratio-only, UID is not a secret>

## Next actions
<Ordered, small, each one verifiable.>
```

Rules for `.agents/context.md`:
- **Decisions is append-only.** You may add rows. You may never rewrite or remove one.
- If you discover that something recorded here is now false, add a new row that supersedes it
  and say so — do not quietly edit history.
- Never write a secret, token, Wi-Fi password or API key into this file.

## STEP 3 — Write the workspace rule

Create or refresh the Antigravity workspace rule so these constraints are active on every turn
of this session **and every future one**.

Write **`.agents/rules/00-racksense-core.md`** with exactly this frontmatter, then the full body
of `rules.md` below it:

```markdown
---
trigger: always_on
---

<paste the complete body of rules.md here>
```

Then write these three scoped rules:

**`.agents/rules/10-contract.md`**
```markdown
---
trigger: always_on
---
The API contract in shared/api-contract.md is the single source of truth shared by the backend
and the frontend. Never add, rename or remove a field, endpoint, enum value or error code on one
side only. To change anything: bump CONTRACT_VERSION, edit shared/api-contract.md, update both
sides in the same change, and append to its Changelog.
```

**`.agents/rules/20-frontend.md`**
```markdown
---
trigger: glob
globs: "*.tsx, *.ts, *.css"
---
<the Frontend Standards section of rules.md>
```

**`.agents/rules/30-backend.md`**
```markdown
---
trigger: glob
globs: "*.py"
---
<the Backend Standards section of rules.md>
```

Also write **`AGENTS.md`** at the repository root containing the body of `rules.md`, so the
rules apply even in tools that read `AGENTS.md` rather than `.agents/rules/`.

Format rules that matter — a malformed rule file is **silently discarded**:
- Frontmatter must use lowercase `trigger:` with one of `always_on`, `model_decision`, `glob`,
  `manual`. `alwaysOn` or any camelCase value is dropped without warning.
- `model_decision` requires `description:`. `glob` requires `globs:`.
- Quote any glob pattern that starts with `*`.
- Only **immediate** `.md` children of `.agents/rules/` are read. Do not nest them in folders.
- Keep each rule file under 24,000 bytes.

---

## STEP 5 — At the end of every run, close the loop

Before you report a task finished, always:

1. Regenerate `graph.md` from the code as it now stands.
2. Update `.agents/context.md` — state, subsystem table, new decision rows, next actions.
3. State in one line what changed in the contract, or say "contract unchanged".

A run that edits code without refreshing the graph and the context is **not finished**, no
matter how good the code is. The next session's correctness depends on those two files being
true.
